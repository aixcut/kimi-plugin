# Kimi 本机素材桥安全整改设计

## 调研结论

根据用户提供的 Kimi 官方文档查证，公开文档没有承诺插件可依靠 `NODE_OPTIONS` 文件代理、后台 Node 子进程或 localhost 桥接来读取本机文件。另一方面，静态检查明确要求保留宿主注入的文件访问配置；本机素材桥的代码注释也表明该配置是宿主文件代理。`NODE_OPTIONS` 是本机观察到的宿主配置，不应描述为 Kimi 公开承诺的 API。

因此，“文档没有说明”不能直接推成“必须删除桥”。需要验证的是：保留宿主配置后，桥能否在授权有效时受控读取；失效时能否停止，而不改走裸文件系统。若做不到，才安全降级到 Project 页面文件选择。

已确认的页面选择入口是 AIXCut MCP 的 `aixcut_frontend(action="prompt_add_material")`，由用户在 Project 页面选择文件。Kimi 文档参考：[Kimi 插件帮助](https://www.kimi.com/help/plugins-and-skills/overview)、[Kimi Code Plugins](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/plugins)。

## 当前实现与问题

调研基线为 `kimi-plugin` 的 `main` / `origin/main` 同一提交 `c3610c8`。

`scripts/local-media-bridge.mjs` 在用户电脑上启动后台文件服务，但会从子进程环境删除 `NODE_OPTIONS`，使后台进程脱离宿主代理。无法复用旧桥时，代码还会把旧状态中仍存在的路径并入新桥；`--no-reuse` 只跳过复用判断，仍然会合并历史路径。复用分支也需要确认：旧清单若比本次请求多文件，不能把多出的文件和 URL 一并返回。

## 目标与约束

- 保留宿主文件访问配置；不以清理 `NODE_OPTIONS`、普通 `fs` 直读或其他方式绕过宿主控制。
- 每次只开放本次用户明确授权的文件；历史状态本身不是授权。
- 文件授权失效或被撤销时，停止读取、撤销对应 URL，并明确提示重新选择或授权；不得回退到无代理的直接读盘。
- `--no-reuse` 必须新建仅含本次文件的桥；过期授权不能因重建而续期。
- 历史文件只有在用户当前逐个确认、宿主当前仍授权且当前来源/任务范围匹配时才可续用。
- 只改 Kimi 插件包、测试和 Skills；不改 MCP Server 部署，也不顺带更新 WorkBuddy 包。

## 方案比较

1. **只删历史文件合并。**不够：仍然会绕过宿主文件代理。
2. **保留桥并按宿主代理失败关闭。**首选：子进程继承宿主配置；每次只服务当前明确清单；授权失败就停止，不使用裸 `fs` 兜底。需在真实 Kimi 环境验证代理生命周期。
3. **若真实宿主下无法证明受控读取有效，则回退网页文件选择。**这会降低本机路径自动导入便利，但仍能通过 `prompt_add_material` 完成导入。

## 推荐设计

移除 `bridgeChildEnv` 对 `NODE_OPTIONS` 的过滤，让后台子进程继承宿主环境。启动前要求存在宿主的 `--require`/`--import` preload 配置；没有该配置时不启动桥，并让 Skill 调用 `prompt_add_material`。配置存在但读取遇到权限拒绝、文件代理断连或其他文件读取失败时，撤销该文件 URL，不尝试直接读盘；若本次重新检查授权失败，也先停止旧桥，避免旧 URL 继续读取。

新桥的文件列表严格等于本次用户明确给出或重新确认的路径集合，不从历史状态追加。每次调用都逐个通过当前宿主配置检查路径；复用还要求 Origin、有效期、策略版本和完整文件集合匹配，并核对后台桥当前仍开放的文件 ID。旧策略版本的桥不复用。旧集合多出 A、本次只授权 B 时，必须安全停止旧桥，让新桥只服务 B。`--no-reuse` 强制停止旧桥并且只开放本次文件。`--status` 不回显历史路径或 URL；导入结算后关闭桥。

Kimi 官方文档未公开承诺后台代理 API，因此是否保留自动导入能力要由真实 Kimi 环境的授权有效、授权失效和重新选择测试确认。若该代理无法在受控权限下工作，使用网页选择作为本机素材的安全回退；这不是把宿主权限绕过后继续读盘。

## 影响范围

成功路径保持“当前任务明确给出/确认本机路径后自动导入”；缺少宿主 preload 配置或代理不可用、权限失效时，用户需要在 Project 页面重新选择。自动化测试用受控 preload 模拟宿主注入与授权撤销，真实 Kimi 会话下的代理生命周期仍需手工验证。MCP Server 运行代码和接口、其他宿主的导入、WorkBuddy 插件包均不在本次变更范围内。
